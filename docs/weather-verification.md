Рядом сохранены исходные публичные ответы. Это реальные ответы API, не генерация.

ступицы нет; температура 2 м не обозначается как температура на высоте турбины.

## Источник и доступность

[Single Runs API](https://open-meteo.com/en/docs/single-runs-api) документирует
отдельные инициализации ECMWF IFS HRES с 14.03.2024, циклы 00/06/12/18 UTC.
Архив остальных моделей по документации начинается позже тестового февраля.
[Historical Forecast](https://open-meteo.com/en/docs/historical-forecast-api)
склеивает прогоны и не заменяет отдельный запуск. Historical Weather, reanalysis,
текущая погода, best-match и seamless здесь не используются.
[ECMWF API](https://open-meteo.com/en/docs/ecmwf-api) описывает нативные уровни ветра
10/100 м и температуру 2 м; первые 90 часов HRES имеют часовую детализацию.
Каждый час фактического ответа всё равно проверяется.

Проверенные ответы не содержат initialization/publication/availability timestamps.
Инициализация привязана к точному `run` в URL; `generationtime_ms` — длительность
обработки, не дата публикации. [Model Updates](https://open-meteo.com/en/docs/model-updates)
различает initialization, modification и availability **последнего** запуска,
а также задержки репликации. Текущая metadata не доказывает историческую доступность
февральского прогона. Историческое время публикации — **UNKNOWN**.

Политики:

- `observed`: available_at = downloaded_at. Скачанный сегодня прогноз не допускается
  к историческому T. Заранее сохранённый live-прогон допустим при более позднем T.
- `assumed`: available_at = initialized_at + delayHours; обязательны rationale и
  approvalReference. Задержки по умолчанию нет. 12 ч в тестах — тестовая политика,
  не согласованная методика. Для реального бэктеста владелец методики должен утвердить
  консервативную задержку и основание. Ссылка на согласование — аудиторские метаданные,
  не механизм авторизации.

published_at остаётся null. Инициализация сама по себе никогда не становится
available_at. Допущение сохраняется в каждом артефакте и должно быть видно в S04/S08.

## Интерфейсы и поведение

`src/server/connectors/weather/open-meteo.ts`:

- `list_runs(as_of)` перечисляет **кандидатные** шестичасовые циклы в ограниченном
  окне (48 ч по умолчанию, максимум 120). Это не подтверждённый каталог: endpoint
  списка не документирован. В observed-политике available_at кандидата = null.
- `fetch_run(run_id, as_of)` использует только Single Runs / ecmwf_ifs, проверяет
  UTC/цикл/доступность, применяет timeout 15 секунд. Возвращает raw как base64 точных
  байтов, SHA-256, координаты запроса, URL, initialized_at, downloaded_at,
  available_at, nullable published_at и допущение. Координаты сетки и units есть в raw.

`src/server/data/weather/selection.ts`:

- `targetHours`: T на границе часа UTC, горизонт 24/48; целевые метки T+1h…T+Nh.
  Convention метки интервала нужно согласовать с S01.
- `validateRun`: проверяет происхождение, текущую политику, available_at <= T,
  хеш, JSON, единицы, длины массивов, порядок/уникальность времени, каждый целевой
  час и конечные ненулевые-не-null значения (числовой ноль ветра разрешён).
- `selectWeatherRun`: кандидаты от нового к старому; успех только после
  `repository.save`. При ошибке сети/HTTP — только сохранённый допустимый полный
  прогон с повторной проверкой raw/hash. Из сохранённых выбирается новейшая
  инициализация; при равенстве — SHA-256 для детерминизма. Результат содержит
  fallback и безопасную причину. Нет подходящего прогона — `NO_ADMISSIBLE_RUN`,
  сбой хранилища — `PERSISTENCE_ERROR`. Фактическая погода не запрашивается.

`types.ts` — локальный типизированный порт S03 согласно правилу SLICES.md о
независимой разработке через интерфейс; это не замена центральных контрактов.
S01 должен предоставить адаптер `WeatherRepository`:

1. `save`: атомарно и неизменяемо сохранить raw/hash/metadata и канонические погодные
   значения с target_time/units; тот же хеш идемпотентен, другой создаёт ревизию.
2. `list_saved`: читать по source/model/координатам и available_at <= T с raw из
   постоянного хранилища, не обрезая список до одного потенциально неполного прогона.
3. Сопоставить с WeatherRun / WeatherRunReader и проверить транзакции и восстановление
   после рестарта на PostgreSQL. Проверка доступа остаётся обязанностью вызывающего слоя.

**Реального PostgreSQL adapter и интеграционного теста нет**: S01 не опубликован.
In-memory repository существует только в тестах. Fallback после рестарта приложения
не заявляется. Unit-тесты не заменяют это подключение и не закрывают весь S03.
