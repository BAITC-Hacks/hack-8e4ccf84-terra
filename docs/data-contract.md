# Контракт входных данных S00 / E1

Дата проверки: 2026-09-23. Версия: 1. Статус: фактический формат подтверждён; семантические блокеры открыты. Основания: CSV и PDF в `resources/`, `PLAN.md` FR-01–03, §15, `SLICES.md` S00. Числа, хеши и воспроизводимая проверка: [аудит](data-audit.md).

## Источники и mapping

В `resources/` ровно два CSV `Dataset HackAlemAI для участников 11.03.2023-28.02.2026 - turbine 1.csv` и аналогичный `turbine 2.csv`; один PDF `HackAlem AI_ Agentic AI для прогнозирования выработки ВЭС.pdf`. Имена файлов не определяют фактический период.

Оба CSV: UTF-8 без BOM, запятая между полями, точка в десятичных числах, одна строка заголовка, пять столбцов. Каждая запись относится к отдельному исходному ряду; предлагаемые локальные ключи `turbine-1-source` / `turbine-2-source` не являются подтверждёнными ID оборудования.

| Исходный заголовок (точно) | Предлагаемое поле | Тип и смысл |
|---|---|---|
| `ID` | `source_row_id` | Целое, последовательность с 1 внутри файла; не глобальный ID |
| `Статистическое время` | `source_timestamp` | Строка `YYYY-MM-DD H:mm:ss`; встречаются часы без ведущего нуля; зона отсутствует |
| `Средняя скорость ветра(m/s)` | `wind_speed_m_s` | Конечное десятичное число, м/с по заголовку и PDF |
| `Нормализованная активная мощность` | `power_normalized` | Конечное десятичное число в исходной нормализованной шкале; формула неизвестна |
| `Средняя температура окружающей среды(°C)` | `ambient_temperature_c` | Конечное десятичное число, °C по заголовку и PDF |

В файлах нет координат, номинала, timezone, признаков качества, времени публикации/доступности, направления ветра, высоты датчика и формулы нормализации. Сохранять raw-файл, SHA-256, исходную строку/ID и версию mapping. API и миграции здесь не реализованы; имена полей служат передачей требований S01/S02.

## Временная шкала и агрегация

Подтверждено для обоих рядов: 2023-03-11 00:00:00 … 2026-01-31 23:50:00 включительно, базовый шаг 10 минут, пропуски присутствуют. Это не готовый почасовой ряд. Время пока является локальной строкой без установленной зоны, а не UTC.

UNKNOWN: timezone/история смещений, означает ли метка начало или конец десятиминутного интервала либо мгновенный замер, является ли мощность средним за интервал. Следовательно, смысл метки начала/конца часа также не установлен. Географическое положение и зона рабочего компьютера не доказывают зону CSV. Не добавлять `Z` и не сдвигать время по догадке.

До канонического импорта обязательны подтверждённые `source_timezone`, смысл метки, длительность/тип измерения и правило доступности. Предпросмотр raw допустим, итоговый прогноз и погодное совмещение блокируются. После подтверждения сохранять исходную зону и переводить абсолютные времена в UTC с историческими правилами смещения.

Проектное правило (не факт источника): канонический час помечается началом интервала `[h, h+1h)`. Для подтверждённых десятиминутных средних: метка начала `t` задаёт `[t,t+10m)`, метка конца — `[t-10m,t)`. Сначала восстановить интервалы, затем распределить их по часам. Например, запись `01:00` попадёт в разные часы при этих двух соглашениях. Мощность усреднять с весами длительности, не суммировать; при шести равных интервалах это арифметическое среднее. Для мгновенных отсчётов требуется отдельное согласованное правило.

Покрытие = покрытая неперекрывающимися валидными интервалами длительность / 60 минут. Начальная безопасная политика: только 100% для полного часа; неполные и отсутствующие часы сохраняют флаг/покрытие и исключаются из полного результата. Изменение порога версионировать. Не заменять пропуски нулями, не интерполировать через длинные разрывы. Диагностическая группировка по текстовому часу в аудите не является итоговой агрегацией.

## Мощность и целевой объект

Подтверждено: два раздельных столбца мощности в двух файлах, наблюдаемый диапазон каждого 0…1. PDF, стр. 1, описывает нормализированную активную мощность на стороне линии. Ряды не идентичны: на 141357 общих метках 98463 значения мощности различаются.

UNKNOWN: независимые ли это турбины/линии, общий ли знаменатель нормализации, есть ли потери/общий счётчик, номинал и преобразование в физическую мощность. Значения 0…1 не доказывают деление на номинал: возможны другие преобразования. До ответа организаторов хранить два исходных ряда отдельно; не объявлять два подтверждённых независимых объекта прогноза, не суммировать и не усреднять их в мощность станции. Итоговый объект (турбина, линия или ВЭС) — блокер.

Подпись значения: «Нормализованная активная мощность, исходная шкала». Не обозначать МВт, МВт·ч или процент номинала. Мощность не равна энергии; перевод требует подтверждённых физических единиц и интегрирования по времени. Сохранять необычные значения с флагами; не обрезать автоматически к [0,1]. Параметры любых новых преобразований обучать только на train.

## Февраль 2026: evaluation-only

PDF, стр. 1: история до 31.01.2026 включительно, тест 01–28.02.2026, последовательные выпуски начиная с 31 января; использовать доступные на момент выпуска архивные прогнозы погоды. Консервативная политика проекта из SLICES/PLAN: февральские целевые значения — только оценщику, пока организаторы явно не разрешат лаги.

- Граница теста — `[2026-02-01 00:00, 2026-03-01 00:00)` в подтверждённой зоне/интервальной шкале источника, затем перевод в UTC. Сейчас точная UTC-граница UNKNOWN.
- В текущих CSV февральских строк **0**. При появлении файла их изолировать по интервалу цели, не по имени файла; пересекающие границу интервалы не включать в train до разрешения семантики времени.
- Нельзя использовать февральскую мощность для обучения, подбора гиперпараметров/модели, нормализации, заполнения пропусков, baseline, признаков/лагов или выбора результата по метрике февраля. Запрет действует и после виртуального наступления этой даты, пока политика не пересмотрена явно.
- История до февраля также допустима лишь при `available_at <= issued_at`; CSV не сообщает задержку поступления. Полночь/полдень выпуска и задержку нельзя выдумывать. Скейлеры, импутация и временная валидация используют только разрешённую историю.
- Фактический будущий ветер/температура из CSV не заменяют архивный прогноз. Вход погоды должен иметь подтверждённую доступность на момент T. Архивных погодных прогонов в `resources/` нет.
- Оценка выполняется после фиксации прогнозов, на доступных валидных февральских целях; показывать N, покрытие и исключения. Без факта статус «нет данных для оценки», не нулевая ошибка. Мартовские хвосты 48-часовых прогнозов не входят в февральскую метрику.
- Критерий для будущих S02/S04/S08: изменение любого февральского факта не меняет снимок входов, модель и прогноз; может менять только оценку. Это требование, а не уже выполненный тест приложения.
