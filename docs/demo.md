## Backup / restore

**Не выполнено: BLOCKED S01.** Имена Compose-сервисов, путь artifact volume и миграции пока отсутствуют. Следующие команды — шаблон для Bash на изолированной demo-среде с PostgreSQL client tools той же основной версии, что сервер. Они не являются проверенной процедурой проекта. S01 должен подставить фактические пути и способ остановки всех писателей (приложение и dispatcher) до финальной приёмки.

1. Приостановить все писатели и дождаться завершения текущего шага. Зафиксировать snapshot_id, model_version, прогнозный CSV и SHA-256 всех артефактов. Согласованная копия требует остановки записи и в БД, и в файловый том.
2. Создать новый каталог backup; использовать `PGSERVICE=terra_demo` и `.pgpass` с локальными правами вместо пароля в аргументах. В service-файле указывается исходная БД.

```sh
pg_dump --format=custom --no-owner --file=backup/database.dump
# ARTIFACT_DIR — фактический путь тома из Compose S01:
tar -C "$ARTIFACT_DIR" -cf backup/artifacts.tar .
sha256sum backup/database.dump backup/artifacts.tar > backup/SHA256SUMS
```

3. Копировать backup в отдельную чистую среду. Проверить `sha256sum -c backup/SHA256SUMS`. Настроить `PGSERVICE=terra_restore` на **новую пустую** БД той же версии; никогда не восстанавливать поверх исходной. Без `--clean`:

```sh
pg_restore --exit-on-error --single-transaction --no-owner --dbname=service=terra_restore backup/database.dump
mkdir restored-artifacts
tar -C restored-artifacts -xf backup/artifacts.tar
```

4. Сверить полный список путей и хеши восстановленных артефактов. Запустить тот же commit с восстановленными БД и томом. Сравнить количество объектов, наблюдений, задач и опубликованных прогнозов, snapshot_id, версии моделей и экспорт до/после. Повторный прогноз на снимке должен дать <= 1e-6; не должно быть повторной публикации старой задачи. Провести AC-11 отдельно при рестарте активной задачи.
5. Записать время backup/restore, exit codes и результаты сравнений. Успешный `pg_restore` сам по себе не доказывает восстановление продукта. Не удалять исходные тома и резервную копию.

## Отчёт качества

Для каждого объекта и lead 1–24 / 25–48 использовать одинаковые ключи `(object, issued_at, target_time)` и одинаковые исключения для модели и baseline. MAE = mean(abs(y-p)), RMSE = sqrt(mean((y-p)^2)). Публиковать N, ожидаемое число пар, покрытие и причины пропусков; при N=0 метрика отсутствует, не ноль. Указать cutoff, модель, baseline, SHA снимка, конфигурацию и commit. Улучшение = baseline MAE − model MAE; отрицательное значение означает проигрыш. Выбор модели по февралю запрещён. Синтетический smoke не доказывает превосходство модели.
